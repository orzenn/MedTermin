# Практическая №2 · ответы для защиты

**Чем MCP отличается от REST и OpenAPI?** REST описывает подход к проектированию веб-API, OpenAPI описывает интерфейс HTTP API. MCP задаёт единый протокол обнаружения и вызова инструментов для хоста. Один и тот же вызов `tools/call` работает через stdio и через сеть; сервер объявляет входную схему, а клиент строит из неё форму.

**Почему нельзя писать `print()` в stdout MCP-сервера?** Клиент ожидает там JSON-RPC, по одному сообщению на строку. Обычный текст повреждает протокольный поток. Сервер пишет журнал в stderr.

**Что несут сообщения JSON-RPC?** Запрос и ответ содержат `jsonrpc: "2.0"`, а одинаковый `id` связывает их. В `initialize` клиент указывает версию, возможности и сведения о себе. В `tools/call` передаёт `params.name` и `params.arguments`. Сервер возвращает `result` либо ошибку. Ошибка самого инструмента может быть внутри `result` как `isError: true`. У нотификации `notifications/initialized` нет `id`, ответ на неё не нужен.

**SSE или stdio для команды?** Дочерний stdio-процесс проще изолировать и не нужно открывать сетевой порт. Отдельный SSE-сервис могут использовать несколько клиентов, но появляются сессии, сбои сети и требования к доступу. Здесь SSE доступен только на локальном адресе.

**Как не передать в калькулятор выдуманное значение?** Отделить сбор данных от расчёта, показать пользователю исходные значения и единицы, требовать подтверждения, оставлять неизвестное пустым. JSON Schema задаёт типы, сервер проверяет диапазоны и связи параметров. Учебные значения подставляются только явной кнопкой. Сам расчёт выполняет детерминированная функция на MCP-сервере; LLM в проекте не участвует.
